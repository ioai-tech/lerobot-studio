# 使用指南

> **Language / 语言：** [English](/user-manual) | [简体中文](./user-manual)

本页介绍如何在独立应用 [lerobot.studio](https://lerobot.studio) 中查看和检查 LeRobot 数据集。

## 打开数据集

按数据所在的位置选择：

| 方式           | 适用场景                                 |
| -------------- | ---------------------------------------- |
| **本地文件夹** | 电脑中已经解压的 LeRobot 数据集          |
| **本地压缩包** | `.zip`、`.tar`、`.tar.gz`、`.tgz` 数据集 |
| **远程压缩包** | 上述压缩包的 HTTP(S) 地址                |

你也可以打开带有 `?url=...` 的分享链接。

本地文件夹和压缩包会在浏览器中处理，不会上传到云端。打开远程链接时，浏览器会向该链接所在的服务器请求数据。

### 最近打开

**打开**菜单会记录最近使用的数据集。如果此前授权过浏览器访问本地文件或文件夹，再次打开时浏览器可能会要求你重新授权。

## 浏览 Episode

在左侧栏选择 Episode。可以通过搜索和筛选找到某个任务，或按时长查看 Episode。

播放条可以：

- 播放或暂停；
- 拖动时间轴跳到指定帧；
- 通过按钮逐帧查看；
- 调整播放速度；
- 在顺序、随机和单集循环之间切换。

键盘快捷键：

| 按键                       | 操作                        |
| -------------------------- | --------------------------- |
| `Space`                    | 播放/暂停。编辑时暂停即标注 |
| `←` / `→`                  | 上一帧或下一帧              |
| `Shift` + `←` / `→`        | 前进或后退 10 帧            |
| `Cmd` / `Ctrl` + `←` / `→` | 前进或后退 5 帧             |
| `↑` / `↓`                  | 上一个或下一个 Episode      |
| `Home` / `End`             | 第一帧或最后一帧            |

## 查看数据

默认布局会让视频、图表和原始特征保持在同一帧。

- **视频 / 图像**显示相机数据。
- **图表**显示数值特征随时间的变化，可选择要绘制的特征。
- **原始数据**显示当前帧的源数据。
- 侧栏中的**分析**显示数据集概览、时长分布和任务分布。

你可以添加面板、向右或向下拆分布局，也可以关闭不需要的面板。

视频能否播放取决于浏览器和视频编解码器。即使视频无法播放，图表和原始数据通常仍可查看。

## 检查数据集

从应用菜单打开**数据集健康检查**，可检查常见格式问题，例如缺少元数据、Episode 数量不正确或文件缺失。检查结果可导出为 CSV。

## 编辑 Episode

对于完全支持的数据集（`v2.1` 和 `v3.0`），可以修改 Episode 的任务描述，批量选择 Episode，并在当前浏览器会话中删除或恢复 Episode。

这些修改只保留在当前浏览器会话中，直到你导出数据集。应用不会覆盖原始文件。

### 标注子任务

可写的 `v3.0` 可在 **编辑** 中标注。`v2.1` 可以查看已有的 `subtask_index`，但不能新增。

- 暂停（`Space`）会从上一段结束（或第 0 帧）标到当前帧。
- 播到 episode 结尾会停在当前集，并弹出最后一段空白。
- 点击进度条空白区可标注该段。
- 可拖拽边缘、双击改名、悬停删除。

只要存在子任务，时间轴就会显示彩色区间，不必打开编辑。官方未标注帧（`subtask_index = -1`）保持空白。缺少 `meta/subtasks.parquet` 时显示为 `Subtask N`。

`v3.0` 导出仅在勾选 **包含子任务** 时写入子任务。勾选后要求每个被导出帧都已标注，且不会写入 `-1`。额外的官方列（如 `task_index_high_level`）会保留。

已验证的 Hub 示例和下载命令见 [数据格式 — 官方 Hub 示例](./data-formats#official-hub-examples)。

`v2` 和 `v3` 系列中较新的 minor 版本可能以只读方式打开。`v2.0`、其他主版本和缺少版本信息的数据集不会打开。

### 拆分与审核 Episode {#split-and-review-episodes}

一段长录制常常包含多次尝试。在 **编辑 Episode** 中把每段有用的范围标为一个*分段*；导出时每个分段写为一个独立的 Episode。没有分段的 Episode 整段导出。

分段以带编号的色带显示在时间轴上方和 Episode 列表中。每个分段包含一个闭区间帧范围、可选的任务（留空则使用 Episode 的任务）、子任务和审核状态：**待审核**（斜纹）或 **已确认**。同一 Episode 中的分段互不重叠。

播放栏下方的详情面板显示选中的分段。**入点** 和 **出点** 是时间（`分:秒.百分秒`）；出点是最后一帧的结束时刻，因此相邻分段共享同一个时间。输入时间后按 `Enter` 应用，按 `Escape` 还原。被拒绝的值会留在输入框中并标出原因。在时间轴上拖动色带边缘可移动边界，边界不会越过相邻分段。

编辑分段永远不会确认它。确认是单独的一步（`A`），且无法撤销。确认后，审核接着进行到列表中显示的下一个待审核分段：它被选中、详情随之打开，播放头暂停在它的起点。没有剩余待审核分段时，状态行会说明。其他所有修改都可以撤销（`Ctrl/⌘+Z`）和重做（`Shift+Ctrl/⌘+Z`），最多保留最近 100 步。

查看器一打开、无需点击，快捷键即可生效，使用查看器期间也一样；在输入框中输入、操作查看器外页面的控件或有对话框打开时不生效。在应用中按 `?` 可查看此列表。

| 按键                          | 操作                                                        |
| ----------------------------- | ----------------------------------------------------------- |
| `N`                           | 从播放头到下一个分段或 Episode 结尾新建分段                 |
| `[` / `]`                     | 把选中分段的入点 / 出点设到播放头                           |
| `,` / `.`                     | 把离播放头较近的边界移动一帧                                |
| `Alt+,` / `Alt+.`             | 把离播放头较近的边界移动一秒                                |
| `S`                           | 在播放头处拆分选中的分段                                    |
| `M`                           | 与下一个分段合并                                            |
| `R` / `Delete`                | 删除选中的分段（撤销可恢复）                                |
| `A`                           | 确认选中的分段，并转到下一个待审核分段                      |
| `Shift+A`                     | 确认当前筛选中所有待审核的分段（会先询问）                  |
| `J` / `K`                     | 列表显示的下一个 / 上一个分段，可跨 Episode                 |
| `G`                           | 跳到下一个不属于任何分段的帧                                |
| `Shift+.` / `Shift+,`         | 可导航标记行中的下一个 / 上一个标记（宿主声明了这样的行时） |
| `L`                           | 在选中分段内循环播放                                        |
| `Shift+[` / `Shift+]`         | 在播放头处开始 / 结束一个子任务                             |
| `Ctrl/⌘+Z` / `Shift+Ctrl/⌘+Z` | 撤销 / 重做                                                 |
| `1`–`9`                       | 选择声明了该按键的字段选项（嵌入式查看器）                  |
| `?`                           | 显示快捷键                                                  |

拆分时两半都保留任务、审核状态和字段值，跨越拆分点的子任务会被切开。新建的分段（`N`）沿用它前一个分段的任务（没有则沿用后一个）；Episode 中还没有分段时，沿用 Episode 的任务。合并时保留第一个分段的任务和字段值，合并标签列表；只有两个分段都已确认时，合并结果才是已确认。

列表筛选可显示 **全部**、**待审核** 或 **有问题**（宿主标记的分段）。建议的分段在确认前会显示建议方的置信度（例如“建议 · 置信度 82%”）。分段保留在当前浏览器会话中，直到导出。

窗口较矮或较窄时（例如 1024 × 768 的笔记本屏幕），详情面板改为紧凑布局：审核操作以图标排成一行（悬停时显示操作名和按键），较少用的操作（设置入点 / 出点、移动边界、下一个未覆盖、循环、子任务、撤销 / 重做、快捷键）收在 **更多操作** 中，按键照常可用。

### 根据动作建议分段

在 Episode 侧栏点击 **选择**，勾选 Episodes，再点击 **建议分段**。操作范围是当前筛选列表内选中的 Episodes。支持两种方式：

- **裁去固定时长**：建议一个从原始 Episode 头尾各去掉指定秒数的范围。长度不足的 Episode 会跳过。
- **自动建议保留区间**：根据位置或夹爪状态检测运动，再保留动作前后的缓冲。两侧默认各 **3 秒**。可选择状态特征、灵敏度和参与检测的维度。默认跳过已有分段的 Episode，勾选替换后才会替换。

检查每条建议的范围、裁去时长和状态。点击范围可在播放器中预览并调整，然后返回建议列表。点击 **添加为待审核分段** 后，每个 Episode 会新增一个斜纹的待审核分段；此前不会改变任何内容。整批添加是一个撤销步骤。未添加就关闭对话框会丢弃建议。

检测使用数值状态的短时窗口、噪声阈值和保守边界余量，保留动作中间的停顿，不分析视频，也不识别任务语义。低频传感器漂移、极慢运动和回位动作可能被当作有效动作，需要结合实际录制数据检查灵敏度和维度选择。整段静止、数据缺失或无效、样本不足时不给出建议；持续运动则保留整段。

### 分段如何导出

每个分段导出为一个 Episode，只包含该分段的数据行：帧号和时间戳从 0 重新开始，子任务标注裁剪到分段内，Episode 任务为分段的任务。Episode 索引按顺序重新编号。数值统计重新计算；RGB/灰度图像统计按每个相机最多 100 帧均匀采样，包含首尾帧。原始文件不会改变。

`v3.0` → `v3.0` 不勾选 **移除视频文件中的未使用片段（较慢）** 时快速导出：复制共享 MP4，每个分段的视频引用指向其中的对应区间；勾选后也会物理裁剪视频。其他版本组合会裁剪视频。重编码需要浏览器支持相应编解码器，可能改变画质或文件大小。支持恒定帧率的 RGB/灰度数据集；不匹配的时间戳、原始深度/TIFF 统计、缺失帧或编解码失败会明确报错，不会生成看似完整的数据集。

## 导出数据集

独立应用可以导出受支持的 `v2.1` 和 `v3.0` 数据集。

- **ZIP** 导出适用于支持的浏览器。
- **文件夹**导出需要浏览器提供文件夹选择功能，通常在 Chromium 浏览器中可用。
- 可以导出为 LeRobot `v2.1` 或 `v3.0`。
- `v3.0` 有 **包含子任务** 选项，默认关闭。勾选后才会写入 `subtask_index` 和 `meta/subtasks.parquet`，并要求每个导出的 episode 都已完整标注。

导出的数据集会包含当前的 Episode 修改。React npm 包不包含导出引擎。

`v3.0` → `v3.0` 默认对仍被引用的共享 MP4 只复制一次，并保留每条 Episode 的视频时间区间；重写保留的 Parquet 数据行和数据划分范围，不重新编码视频。删除的 Episode 不再被数据集读取，但其画面可能仍在共享视频文件内；完全没有剩余引用的文件不会导出。需要实际裁去未使用画面时，勾选 **移除视频文件中的未使用片段（较慢）**。裁剪可能触发视频重编码并增大文件，因此删除 Episode 不保证 ZIP 更小。
